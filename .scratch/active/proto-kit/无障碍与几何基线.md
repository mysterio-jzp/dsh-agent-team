# 无障碍与几何基线（本轮四份界面共用）

> 这份是**可执行的判据**，不是原则宣言：每一条都能在浏览器里断言或量。
> 各工作项的 `validation/设计判据.md` 引用本文件，⛔ 不各抄一份。

## 一、键盘与焦点

| # | 判据 | 怎么验 |
|---|---|---|
| K1 | 每个可点目标都能 Tab 到，顺序与视觉顺序一致 | 只用 Tab 走一遍原型：产物条目卡 → 页签 → 认领按钮 |
| K2 | 焦点环可见且只有一种写法：`outline: var(--dsw-focus-ring-width, 2px) solid var(--dsw-focus-ring-color, var(--dsw-alias-state-business-primary))`，行内控件 offset 2px、列表行 -2px | 逐个 Tab，环不能消失、不能换色 |
| K3 | 右侧面板关闭后焦点**回到触发它的那张产物卡** | Esc／✕ 各关一次，看焦点落点 |
| K4 | 面板内 Esc 可关；`?`／`aria-keyshortcuts` 不必新增 | 面板打开时按 Esc |
| K5 | 页签是 `role="tablist"` ＋ `aria-selected`，左右方向键可切换 | 焦点在第一个页签上按 → |

## 二、读屏与语义

| # | 判据 | 怎么验 |
|---|---|---|
| S1 | 纯图标控件必须有 `aria-label`（回复、复制链接、关闭面板、上移/下移/移除目录、⋯） | 逐个查可访问名 |
| S2 | 计数徽标的数字在**控件自身的可访问名**里（"N 条待办需要我处理"），⛔ 不能只存在于视觉徽标 | 查名册行与频道行的可访问名 |
| S3 | 「有人@我」标记是文本节点（含 `@`），⛔ 不加旁挂图标（图标＋已含 `@` 的标签＝双标记） | 查 DOM |
| S4 | 加载态用 `aria-busy="true"` ＋ 禁用；结束后清掉 | 查加载帧 |
| S5 | 幂等提示走 `role="status"` ＋ `aria-live="polite"`，⛔ 不用 `alert`（不是错误） | 点「认领」两次 |
| S6 | 产物条目卡的可访问名说清"打开产物预览：<文件名>"，⛔ 不读成一串路径 | 查可访问名 |
| S7 | 头像图片有替代文字；纯装饰的头像座位 `aria-hidden="true"`（作者名在同一身份行上） | 查 DOM |
| S8 | 状态不靠颜色单独承载：待办四态都有文字状态词（待认领/已认领/已回复/已结案） | 灰度看一眼 |

## 三、对比度（2026-10-14 逐个算过）

正文阈 4.5:1，非文本/大字阈 3:1（WCAG 2.1 AA）。

| 配对 | 浅色 | 深色 |
|---|---|---|
| 正文 / 气泡 | 16.96 ✅ | 11.98 ✅ |
| 次要文字 / 气泡 | 5.21 ✅ | 6.53 ✅ |
| 三级文字 / 页底 | 3.71 ⚠（承载时刻、路径等小字，见下） | 6.68 ✅ |
| 最小字号 caption / 页底 | 2.13 ❌ | 4.92 ✅ |
| 「有人@我」/ warn 底 | 8.39 ✅（用 amber **深档** 120,53,15） | 8.08 ✅ |
| 待认领签 / 卡片 | 9.07 ✅ | 8.08 ✅ |
| 已认领签 / business 浅底 | 7.17 ✅（用 blue-800 30,64,175） | ✅ |
| 计数徽标白字 / 底 | 5.02 ✅（用 amber-700 180,83,9） | ✅ |
| 头像首字母白字 / 色相底（既有 46%） | ❌ **360 度里 186 度不达标**，最差 hue 60 仅 **2.54:1** | ❌ 同 |
| 头像首字母白字 / 色相底（拟修 33%） | ✅ 全色相 ≥4.70:1 | ✅ |

**三处刻意偏离既有实现，理由都是对比度**：

1. **计数徽标底色**：shipped 的 `countBadge.module.css` 用 `--dsw-alias-state-business-primary` 配 `--dsw-alias-label-primary-foreground`（实为 `rgb(255,255,255)`，已回源码核过），**4.28:1**，11px/600 小字不达 AA（同一支 `.hairline` 变体是 `label-secondary` 配透明底，那个达标）。原型改用更深的底（中性深底／amber-700 180,83,9 = 5.02:1）。⚠ 这是**既有实现的问题**，不是我新造的；要不要顺手改 shipped 归 @插件开发 定。
2. **头像色相明度**（**已更正，见 §六**）：既有 `hsl(memberHue 42% 46%)` 配白字不合 AA —— 不是"某些色相"，是 **360 个色相里 186 度（52%）低于 4.5:1，区间 hue 21–206，最差 hue 60 只有 2.54:1**。`memberHue` 是 `hash(memberId) % 360`（`team-formatters.ts:81`），取值铺满整圈，所以这不是边角个例。
   拟修值＝**明度 33% 或更低**（实测 33% 起全色相 ≥4.70:1；34% 仍有 4 度落在 4.45:1）。⚠ 我先前交付时写的 **36% 是错的**（36% 下 hue 52–92 仍有低于 4.5:1 的色相，最差 4.04:1）—— 那是我只抽了 4 个实际用到的色相就下了结论，已按全色相扫过更正。
   **当前冻结原型用的是既有 46%**（画的就是"今天会落地的样子"）；修不修＝@jzp 的第 9 条，修则落在独立一笔 `fix/contrast-baseline`，改前必须全色相扫一遍。
3. **amber 分两档用**：`--dsw-alias-state-warn-label`（221,134,41）白底只有 2.79:1 ⇒ 只用作**描边**（非文本，3:1 阈下勉强）；小字一律用派生深档（120,53,15）。

**两处我没能改好、也⛔ 不该在这轮悄悄改的**：`label-tertiary`（3.71:1）与 `label-caption`（2.13:1）是 shipped 主题 token，小字用它就是达不到 AA —— 它们在既有界面里也是这个读数。原型里承载"时刻／路径／元信息"的地方我已经尽量改用 `label-secondary`；剩下的按默认沿用 shipped 读数，**要不要提"小字对比度"这笔，归 @jzp**。

## 六、更正记录（2026-10-14）

| 我先前写的 | 实际 | 怎么错的 |
|---|---|---|
| 头像明度取 **36%** ⇒ "每个色相都 ≥4.5:1" | **错**。36% 下 hue 52–92 仍有不达标色相，最差 hue 60 只有 4.04:1 | 只抽了原型里实际用到的 4 个色相（44／174／212／302）就下了普遍结论；`memberHue` 实际铺满 360 度 ⇒ 必须全色相扫 |
| 头像既有值"hue 44 只有 3.24、hue 174 只有 2.89" | 数字对，但**说法偏轻**：不达标的是 **186/360 度**（52%），最差 **2.54:1** | 同样是抽样陈述，读起来像"个别色相" |

**教训（写进我自己的规矩）**：凡是"某个值×某个函数生成的取值空间"的对比度结论，⛔ 不能抽样——`memberHue` 是 `hash % 360`，就得 360 度全扫一遍再写数。
